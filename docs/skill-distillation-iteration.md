# 视频 Skill 蒸馏与迭代闭环

## 目标

将游戏视频中的可复用操作经验，从“视频内容总结”提升为可执行、可验证、可迭代的 Skill。

核心闭环：

`视频 → Skill v0.1 → 实际执行 → 观察结果 → 误差分析 → 修正 → Skill v0.2 → …`

## Skill 数据模型

每条 Skill 至少描述：

- `state`: 当前游戏状态
- `signal`: 玩家观察到的视觉/声音/节奏信号
- `action`: 对应操作
- `timing`: 操作触发时机
- `result`: 执行结果
- `error`: 失败类型，例如提前、延迟、动作错误
- `adjustment`: 下一轮修正策略
- `version`: Skill 版本号
- `evaluation`: 当前验证指标

## 游戏节拍示例

将音乐/节奏作为输入信号时，不把音乐本身当作最终语义，而建立状态映射：

| 节奏信号 | 游戏事件 | 玩家动作 |
|---|---|---|
| 弱拍 | 机甲抬脚 | Shift 闪避 |
| 空拍 | 机甲换弹 | 切武器 / 换弹 |
| 重音 | 机甲开炮 | 左键攻击核心 |
| 休止 | 机甲倒地 | 走位 + 补枪 |

## 反馈闭环

`观察 → 行动 → 检查 → 调整 → 下一轮`

每次动作后记录：

1. 是否命中预期状态？
2. 动作是否成功？
3. 如果失败，是提前、延迟还是动作选择错误？
4. 下一轮应该如何修改触发时机或动作条件？

## 目标函数示例

第一版实验可以使用可量化指标：

- 机甲核心血量低于 30%：进入易损状态
- 成功打断施法 2 次：视为进入稳定节奏
- 闪避成功率达到 80%：视为当前 Skill 基本掌握

这些阈值属于实验参数，应通过实际数据继续迭代，而不是视为固定事实。

## 版本化原则

不要直接覆盖旧 Skill。每次经过实验验证的修改都产生新版本：

```text
Skill/
├── v0.1/
├── v0.2/
├── v0.3/
├── evaluation/
├── failures/
└── best/
```

更新规则：

`原 Skill → 实验 → 数据 → 评价 → 达到阈值 → 新版本`

失败版本保留，方便回溯和比较。

## MVP 路线

第一阶段：输入一个游戏视频，人工或模型提取状态、信号、动作、时机和结果。

第二阶段：生成结构化 Skill v0.1。

第三阶段：使用新的游戏视频/实战记录验证 Skill。

第四阶段：根据失败样本自动生成修正版 Skill。

第五阶段：比较多个版本的成功率、时序误差和稳定性，选择最佳版本。

## 设计原则

**视频不是答案。视频是训练样本。**

**音乐不是动作。音乐是输入信号。**

**游戏状态提供语义。**

**动作是输出。**

**反馈负责验证。**

**迭代负责让 Skill 变准。**
